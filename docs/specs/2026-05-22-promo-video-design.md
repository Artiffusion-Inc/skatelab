# SkateLab — Проморолик: Дизайн-документ

**Дата:** 2026-05-22
**Формат:** 30-60 сек, 9:16 (Reels/TikTok) + 16:9 версия для сайта
**Подход:** Живая съёмка на катке + UI-симуляция в постпродакшене (mockup overlay)
**Монтаж:** Ищется специалист (motion-designer / видео-монтажёр)

---

## Концепция

AI-тренер по фигурному катанию: от датчиков → видео → анализ → постановка → прогресс.
Эмоция: от «слепой» тренировки к системе, где каждая ошибка видна и исправляется.

---

## Раскадровка (6 сцен, ~45 сек)

### Сцена 1: Надевание датчиков (3 сек)

**Живая съёмка:**
- Крупный план: руки крепят WitMotion WT901 на конёк (липучка + EVA-прокладка)
- Второй датчик на второй ботинок
- Крупно: синий LED-индикатор на датчике загорается

**UI overlay:** Нет (чисто живые кадры — показываем физический продукт)

**Реквизит:**
- 2× WitMotion WT901 BLE CL
- Крепления (липучка + EVA-прокладка)
- Коньки фигурные

**Замечания по продукту:** Датчики физически существуют, BLE-код в Android app готов. Для съёмки достаточно показать крепление — не нужен рабочий app на камере.

---

### Сцена 2: Спортсмен катается + тренер записывает (5 сек)

**Живая съёмка:**
- Средний план: фигурист выполняет элемент (прыжок — axel или lutz)
- Крупно: конёк с датчиком в движении (лед, брызги)
- Тренер держит телефон/планшет, снимает прокат

**UI overlay:** Нет (живые кадры — показываем контекст использования)

**Реквизит:**
- Фигурист в форме с датчиками на коньках
- Тренер с телефоном
- Каток

---

### Сцена 3: Разбор ошибок по видео (10 сек)

**Живая съёмка:**
- Съёмка со спины: спортсмен и тренер смотрят в телефон/планшет
- Тренер показывает на экран, объясняет

**UI overlay (mockup на экране устройства):**
Симулированный экран телефона/планшета с:

1. **VideoWithSkeleton** — видео проката с наложенным скелетом (H3.6M 17 ключевых точек)
2. **PhaseTimeline** — полоса внизу с отмеченными фазами (толчок → пик → приземление)
3. **Рекомендации** — список на русском:
   - «Колени слишком прямые при приземлении (42° вместо 70-90°). Старайтесь приземляться на более согнутые колени.»
   - «Недостаточная скорость вращения (450°/с вместо 600+°/с). Работайте над группировкой.»
   - «Корпус наклонён вперёд 0.3с после приземления. Удерживайте вертикаль.»
4. **Метрики** — карточки с цветовой индикацией (зелёный/красный):
   - Высота прыжка: 0.42 м (красный — ниже нормы 0.55+)
   - Угол колена при приземлении: 42° (красный — ниже нормы 70-90°)
   - Скорость вращения: 450°/с (красный — ниже нормы 600°/с)
   - GOE оценка: 4.2/10

**Mockup-требования к motion-designer:**
- Скелет поверх видео: 17 точек, соединённых линиями, цвет по confidence
- Фазовая полоса: зелёный (толчок) → жёлтый (полёт) → красный (приземление)
- Карточки метрик в стиле Nike design system (flat, pill buttons, 20px radius)
- Рекомендации на русском с иконкой ⚠️

**Продуктовые данные для mockup:**
Взять из demo session JSON (`frontend/public/demo/session.json`) или из seed_demo.py.

---

### Сцена 4: Постановка программы (10 сек)

**Живая съёмка:**
- Тренер за ноутбуком/планшетом, загружает музыку
- Тренер нажимает кнопку (крупно палец на кнопке «Сгенерировать»)

**UI overlay (mockup экрана):**

1. **Музыка загружена** — WaveformView (визуализация аудио), BPM: 132, тональность: A minor
2. **Инвентарь элементов** — список: 3T, 3F, 3Lz, 2A+3T, CCoSp4, StSq3
3. **Кнопка «Сгенерировать программу»** — нажатие → загрузка 1 сек
4. **Карта катка** — SVG rink 60×30 м с элементами:
   - Круги (прыжки) на разных позициях катка
   - Ромбы (вращения)
   - Пунктирные линии (переходы между элементами)
   - Оценка TES: 58.3 балла

**Mockup-требования к motion-designer:**
- Rink diagram: олимпийский каток с разметкой (круги, линии)
- Элементы: цветные маркеры (круги/ромбы) с подписями (3T, 3F и т.д.)
- Переходы: пунктирные Bezier-кривые
- Анимация: элементы появляются последовательно по таймлайну
- Score bar сверху: TES 58.3

**Продуктовые данные для mockup:**
Rink SVG из CSP solver. Прогнать `generate` endpoint с реальным запросом.

---

### Сцена 5: Кадры постановки, тренер смотрит на карту (5 сек)

**Живая съёмка:**
- Фигурист выполняет элементы программы
- Тренер периодически сверяется с планшетом (карта катка)

**UI overlay (mockup на планшете):**
- Та же карта катка из сцены 4
- Текущий элемент подсвечен (пульсирующий маркер)
- Пройдённые элементы — зелёная галочка

**Mockup-требования:** Минимальный — статичная карта + 1 анимированный элемент

---

### Сцена 6: Дашборд прогресса (7 сек)

**Живая съёмка:**
- Спортсмен и тренер смотрят на экран, довольны
- Или: только экран устройства крупно

**UI overlay (mockup экрана):**

1. **TrendChart** — линейный график за 30 дней с заметным восходящим трендом:
   - Ось X: даты тренировок
   - Ось Y: GOE оценка (от 4.0 до 8.5)
   - Зелёная линия идёт вверх
   - Серая полоса — «референс» (норма)
2. **Метрики-карточки** с PR-бейджами:
   - Высота прыжка: 0.58 м ↑ (+0.16) PR 🏆
   - Угол колена: 78° ↑ (+36°) 
   - Скорость вращения: 680°/с ↑ (+230°/с) PR 🏆
3. **Диагностика** — зелёные чекмарки:
   - ✅ Высота прыжка: в норме
   - ✅ Скорость вращения: выше нормы

**Mockup-требования к motion-designer:**
- TrendChart с явным восходящим трендом (данные: 4.2 → 5.1 → 5.8 → 6.3 → 7.0 → 7.8 → 8.5)
- PR-бейджи (зелёные pill с «+X.X»)
- Зелёные чекмарки вместо красных предупреждений (прогресс!)

**Продуктовые данные:** seed_demo.py генерирует 20 сессий с прогрессом. Можно взять тренд оттуда.

## Что нужно подготовить до съёмки

### Продуктовые артефакты (для motion-designer)

| Артефакт | Откуда | Формат | Приоритет |
|----------|--------|--------|-----------|
| Скелет + видео (для сцены 3) | ML pipeline на реальном видео | PNG скриншот + видео с overlay | HIGH |
| Рекомендации на русском | demo session JSON или ML pipeline | Текст | HIGH |
| Карта катка SVG | CSP solver (`/render-rink`) | SVG | HIGH |
| Waveform аудио | Music analysis endpoint | PNG/SVG | MEDIUM |
| TrendChart данные | seed_demo.py или manual mock | JSON массив | HIGH |
| Метрики-карточки | demo session JSON | Стили Nike DS | MEDIUM |

### До съёмки нужно

1. **Прогнать ML pipeline на 1 реальном видео фигуриста** → получить скелет overlay + рекомендации. Это исходник для mockup сцены 3.
2. **Сгенерировать программу через CSP solver** → получить SVG карты катка. Исходник для сцены 4-5.
3. **Сгенерировать TrendChart данные** через seed_demo.py → исходник для сцены 6.
4. **Собрать WitMotion датчики + крепления** — физически готовы для съёмки.

### Живая съёмка — реквизит и план

| Что снимаем | Реквизит | Камера | Длительность |
|-------------|----------|--------|-------------|
| Крепление датчиков (крупно) | Датчики + коньки + руки | Телефон, макро | 30 сек raw |
| Фигурист катается | Фигурист + датчики на коньках | Телефон/камера | 2 мин raw |
| Тренер записывает | Тренер + телефон | Вторая камера | 1 мин raw |
| Разбор (со спины) | Тренер + спортсмен + устройство | Камера | 1 мин raw |
| Постановка (тренер за ноутбуком) | Ноутбук + тренер | Камера | 1 мин raw |
| Катание по программе | Фигурист | Камера | 2 мин raw |
| Дашборд (реакция) | Тренер + спортсмен + устройство | Камера | 30 сек raw |

**Итого raw:** ~8-10 мин, на катке ~1 час со сборкой.

1. **Raw-видео** со съёмки (MP4, 1080p или 4K)
2. **UI mockup-спрайты** (PNG/SVG с прозрачным фоном) для каждой сцены:
   - Скелет overlay (сцена 3)
   - Рекомендации-карточки (сцена 3)

## Риски и митигации

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| ML pipeline не работает на реальном видео | Средняя | Прогнать заранее, исправить баги |
| Датчики не подключаются по BLE | Низкая | На съёмке не нужен рабочий app — только физическое крепление |
| CSP solver даёт некрасивую карту | Низкая | Сгенерировать 10 вариантов, выбрать лучший |
| Motion-designer не найден | Средняя | Начать поиск сейчас, параллельно с подготовкой артефактов |
| Raw-видео некачественное | Средняя | Снимать на 4K, хороший свет, штатив |
