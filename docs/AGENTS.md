# Documentation

- `research/` — evidence and source analysis.
- `specs/` — approved technical designs named `YYYY-MM-DD-<topic>-design.md`.
- `plans/` — executable implementation plans named `YYYY-MM-DD-<topic>.md`.
- `business/` — product, market, finance, legal, and GTM knowledge.

## Rules

- Link to canonical code/config instead of duplicating volatile facts.
- Mark assumptions, estimates, validation status, and source dates.
- Keep plans distinct from completed behavior; update stale status claims.
- Use repository-relative links and verify referenced paths.
- Do not include credentials, private contact details, or raw interview PII.
